# Ciclo de validação de DDL — 19/11/2026

Uma tabela descartável, `ws4_demo.validacao_release`, permite verificar estados intermediários com um novo script, teste e PR por etapa. A criação gera dois ids por identity e duas amostras fictícias. A adição verifica o default nas linhas existentes; a remoção da coluna preserva as amostras; o DROP final remove somente essa tabela, sem CASCADE.

| Versão | Operação |
|---|---|
| 09 | Criar tabela, identity e duas amostras |
| 10 | Adicionar observacao com default e NOT NULL |
| 11 | Remover observacao preservando as amostras |
| 12 | Remover a tabela descartável e suas amostras |

Cada etapa passa por push na develop, quatro checks, PR develop → main, checks finais, merge e workflow de aplicação. A conferência posterior compara estrutura e dados no PostgreSQL e verifica se a tag/release aponta para o commit aplicado. O laboratório usa o merge do proprietário após checks; o processo corporativo com aprovação independente permanece ilustrativo.
